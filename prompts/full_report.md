# wxsummary 完整语义群报｜默认编辑规范 V1.2

用户只需说明「日期或周/月 + 群名」，Agent 默认采用本规范。写稿必须以 **指定时段的真实群消息** 和 `material.json` 的证据 ID 为唯一事实基础，不凭空补充外部情报；在数据源授权前不得读取聊天隐私。

## 一、进入写稿前：验证完整覆盖

逐项确认群名称/ID、时间窗、时区、读到的发言数、数据最新消息时间和生成时间。读取 `material.md` 以及所有 `material.part-N.json`；必须按 `chunks.reading_order` 遍历，不得只看前几条或最后几条。大量消息先按时间块提取候选话题、参与人、原话证据与观点转变，再合并同一议题、去重和按价值排序。对没有同步到电脑的消息不可声称已读取。

## 二、用户默认要求（九项，逐项落实）

1. **刷新**：已有授权的本地刷新工具先执行 refresh；离线导入不能伪称已同步。
2. **核心议题**：优先 5—8 条，以事实价值、时间敏感度、明确结果与行动价值排序，非发言量排序。实际不足时少于 5 条，绝不凑数。
3. **议题深度**：每条写背景、关键观点、真实分歧与目前结论。重要争议须展示各方主张，不把一人观点写成群共识。
4. **资源价值**：精选真实分享的 URL，说明可能用途、适用对象和需核查之处；不访问陌生链接、不假装读过网页全文。
5. **任务行动**：只有明确约定的待办、安排、期限才列出，责任人和时间没有原文就空缺。
6. **原话证据**：每个话题、观点、待办、链接和每日条目都要 `evidence` msg_id；`quotes` 保留原文连续片段，不得改写和编造。
7. **统计为辅**：保留发言数、参与者、活跃时段、重要链接和主要发言者，不能让统计取代语义分析主体。
8. **完整三格式**：写 `semantic.json`，运行 `validate`，然后用 `newspaper` 主题输出 `report.md`、`report.newspaper.html`、`report.newspaper.png`。
9. **拒绝降级**：严禁 `quick` 和 `--stats-only` 冒充语义日报。校验失败就修复，长图失败就披露实际失败，不可静默跳过。

## 三、semantic.json 撰写规则

**顶层**：`version: 1`，`one_liner` 用 30—80 字说清最重要的实质进展；`editor_note` 写本期主线、争议和数据局限；`mood` 可选。

**每个 topics 条目**（保留 `summary` 兼容已有模板）：

- `title`：明确谁做了什么、哪个方案被讨论或形成何种阶段性结论，不要用「话题一」「经验分享」等空泛标题。
- `summary`：2—4 句叙事性综合说明，交代讨论发展的时间或逻辑脉络。
- `background`：1—2 句，交代触发本轮讨论的具体背景。
- `key_views`：2—4 条不同参与者的重要观点，附在 `evidence` 中能够找到的原文支持。
- `debate`：确有分歧则解释争议双方及核心理由；没有实质争议则写「未见明显分歧」，不得编造。
- `conclusion`：写现在能确认到什么程度。如未定论，写「尚未形成确定结论」并指出已知进展。
- `conclusion_status`：只使用 `confirmed`（明确确认）、`leaning`（倾向方案）、`pending`（待确认）、`discussion`（仅讨论）、`individual`（个别观点）。不能因为一人发言就用 `confirmed`。
- `points`：可选，不重复正文的 2—4 条行动性补充要点。
- `quotes`：可选 1—2 条最能代表争议或结论的**逐字**原话，每条最好不超过80个汉字；每条含真实 `msg_id` 和连续原文 `text`。
- `evidence`：包含真实 msg_id，用 1—4 条高相关证据覆盖关键观点及结论，不用大量无关证据凑数。
- `people`、`tags`、`chat_id` 按实际需要使用，不编造群友昵称。

**insights**：只保留有事实价值的共识、争议、洞见与风险，可以为空；`stance` 用 `consensus/debate/insight/warning`，不能把意见伪装成事实。

**follow_ups**：约定事项、负责人、截止时间（只写明确的），可为空。把「有人建议」和「群里已决定」区分开。

**links**：URL 必须来自 `material.stats.links`；`note` 解释为什么值得看，未打开链接时只可依据消息和标题说明潜在价值，不能伪称已证实。

**for_me**：仅在本人身份已配置并有实际点名/@/引用/委托证据时输出，不能把面向全体群成员的一般讨论说成个人任务。

**daily**：周报、月报先按日期写确实有发言的每日要点，再归纳跨日变化。不要重复所有 daily 作为 topics。

## 四、清晰排版与长图阅读

完整的 Markdown/HTML 以正文为主，标题直接指向价值，段落简洁，分背景/观点/分歧/结论。每个话题保留 1—2 条关键引言，完整证据索引放报告末尾，不要正文反复堆砌相同长引用。统计靠后，数据可查但不占主视觉。PNG 长图和 HTML 保持同一事实内容，不把长图做成只有图表的统计海报。

## 五、完整交付检查

完成 `semantic.json` → `python wxsummary.py validate --run "run_dir" --json` → `python wxsummary.py render --run "run_dir" --theme newspaper --format md,html,png --json`。检查 `status.json`、`stats_only=false` 和三种输出的文件路径。至少在用户回复中告知报告覆盖范围、核心发现、待办及文件真实存储位置。没有权限、未读取全部分块、模型不可用、或 PNG 浏览器渲染失败时明确声明限制；严禁虚假成功。
